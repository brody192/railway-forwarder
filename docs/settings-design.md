# Settings design

The Settings layout uses outline SF Symbols in the sidebar. Like Finder, an active window shows blue symbols for every section, white labels and a neutral highlight on the selected section. The active sidebar reveals its native vibrancy background. The content pane stays opaque `#202326` in both active and inactive windows. An inactive window uses opaque `#242c32` for the sidebar. These colours were sampled from the user's Finder reference and confirmed by the user. It keeps the selection with a quieter highlight and grey symbols and labels. Window activation changes update these states immediately. Category icons appear only in the sidebar. Each pane has a text heading. The native window keeps its Settings title for accessibility, while AppKit hides the visible title-bar label.

The sidebar contains navigation only. App branding is omitted there. The menu editor preview contains its read-only header and editable resource rows, without tunnel switches or Disconnect, Settings and Quit commands. The selected resource label has a neutral highlight on the same button bounds as hover, excluding the drag handle and outer row padding. Clicking outside the preview and display-name panels clears that selection; clicking inside either panel preserves it. The actual menu bar menu retains its controls.

The window has no toolbar. Pane content starts at its ordinary top padding, and only the sidebar reserves space for the native window controls. Hiding a title must not leave an empty toolbar-sized strip above the pane.

The menu editor takes its preview and inspector arrangement from the workspace organization visible in [Nova's current interface](https://nova.app/). Both panels have matching external headings and spacing, so their headings and top borders align. At widths of 900 points and above the 350-point preview and display-name inspector sit side by side. Smaller windows stack them in the same scrolling region. The fixed menu commands and port labels remain read-only.

[Raycast's Settings documentation](https://manual.raycast.com/settings) was also reviewed for grouping preferences and keeping search close to the controls it filters. Services retains its existing hierarchy and search behavior, with the selected-port filter in the page heading and search, Clear and Refresh sharing one row.

General uses a Startup group. Account uses an identity card with the user's Railway name, profile photo and email, plus a separate group for project access and session actions. Name and photo come from the existing OAuth profile scope. Photos are fetched without an authorization header and retained only in memory, with initials as a fallback. Signing out clears the identity and photo. These surfaces share spacing, icon sizes, typography and separators through `ui/settings/style.rs`. Port-row padding, selected ports, custom names, menu order and tunnel behavior remain owned by their existing modules.

The app uses an explicit dark palette. An AppKit split-view controller supplies the sidebar background, with an empty source list inside its sidebar item. GPUI owns the visible controls above that native background. `WindowChrome` retains the native controller for the settings view's lifetime and removes its underlay on drop. The underlay follows native window resizing and is hidden from accessibility because GPUI supplies the accessible controls.

Finder 27.2 (1865.1.20) was inspected locally to establish the native setup. Its `TSidebarSplitViewController` creates the sidebar through `sidebarWithViewController:` and calls `_setHasBaseVibrancyEffect:YES` before inserting it. The macOS adapter reproduces those steps, rather than using a general glass surface or a bare blur. The internal setter is isolated there and checked with `respondsToSelector:`; an unavailable selector produces an explicit setup error. Settings content uses opaque surfaces for readability. GPUI continues to own layout, editing, filtering and drag interactions.
